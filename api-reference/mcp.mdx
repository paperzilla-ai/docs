The canonical Streamable HTTP resource is `https://paperzilla.ai/api/mcp`. The server uses Python MCP SDK 2.3.0 with the `2026-07-28` per-request protocol and standard `2025-11-25` client interoperability. Use your SDK to handle version negotiation and request envelopes.

## OAuth

- Issuer: `https://paperzilla.ai/api/oauth`
- Authorization metadata: `https://paperzilla.ai/.well-known/oauth-authorization-server/api/oauth`
- Resource metadata: `https://paperzilla.ai/.well-known/oauth-protected-resource/api/mcp`
- Endpoints under the issuer: `/authorize`, `/token`, `/register`, `/revoke`.

Use authorization code with mandatory PKCE S256. Supply `resource=https://paperzilla.ai/api/mcp` on authorization and code exchange. Callback URLs must match the client's registration; native loopback callbacks follow the SDK's native-client rules. CIMD, dynamic registration, and pre-registered public clients are supported. Set `token_endpoint_auth_method` to `none`. No machine-to-machine grant is available.

The functional scopes are `catalog:read`, `projects:read`, and `markdown:generate`. Request `offline_access` for refresh access. Custom clients can request a subset. Codes expire after five minutes and are single-use. Access tokens last 15 minutes. Refresh tokens rotate and expire after 30 days of inactivity; reuse revokes the connection. Store each replacement before using it again and serialize refresh within the client.

Send only the dedicated OAuth access token in the Authorization header. Do not pass Supabase sessions to the MCP endpoint. Old keys and query credentials are rejected. Standard challenges identify discovery metadata; insufficient tool scopes return `mcp/www_authenticate` metadata.

## Tools

| Tool | Inputs | Scope |
|---|---|---|
| `account_status` | none | `catalog:read` |
| `projects_list` | `limit`, `offset` | `projects:read` |
| `projects_get` | `project_id` UUID | `projects:read` |
| `feed_get` | `project_id`, optional `must_read`, ISO `since`, `limit`, `offset` | `projects:read` |
| `feed_search` | `project_id`, `query` (3–200 characters), optional `must_read`, `limit`, `offset` | `projects:read` |
| `public_digests_search` | optional `query` (up to 200 characters), `limit`, `offset` | `catalog:read` |
| `public_digest_issues_list` | series `project_id`, `limit`, `offset` | `catalog:read` |
| `public_digest_get` | `issue` UUID/short ID/Paperzilla URL, `limit`, `offset` | `catalog:read` |
| `paper_get` | `reference` ID/URL/DOI | `catalog:read` |
| `paper_markdown_get` | `reference`, optional character `offset`, `revision` | `catalog:read` |
| `paper_markdown_request` | `reference` | `markdown:generate` |

`reference` accepts a Paperzilla UUID, eight-character short ID or paper URL; a DOI (including doi.org links); `PMID 12345678` or `pmid:12345678`; an IACR ePrint `YYYY/NNN` identifier; and paper URLs from arXiv, PubMed, IACR ePrint, bioRxiv and medRxiv. arXiv and IACR PDF links are supported. arXiv, bioRxiv and medRxiv version URLs resolve against the existing catalog. bioRxiv and medRxiv URLs use `/content/10.1101/...`. Other website URLs return `not_found` with supported-reference guidance. Paperzilla never fetches the supplied URL or imports a missing paper.

Lists default to 20 results and allow 1–50. Follow `next_offset` until null. Markdown uses 20,000-character pages with a revision hash. Only `paper_markdown_request` is a write. Its 10-request/minute limit is shared by all clients for the account. There is also a general 120-tool-call/minute account limit.

Results are structured and include readable text. `needs_project`, `not_found`, `ambiguous`, `not_ready`, `queued`, `cooldown`, `unavailable`, `restart_required`, and `rate_limited` are product states. Errors do not include internal job IDs or hidden preview content. No legacy aliases or prompts are exposed. Atom remains a separate non-MCP integration.

## Account management

Browser endpoints `GET /api/oauth/connections` and `DELETE /api/oauth/connections/{grant_id}` require the ordinary Paperzilla session. They never accept MCP access tokens. Browser-only consent is bound to a pending request and same-browser cookie; clients must follow `/authorize`, not call the consent endpoint directly.

See [setup and reconnecting](/guides/mcp), the [MCP authorization specification](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization), and the [Python SDK](https://py.sdk.modelcontextprotocol.io/whats-new/).
