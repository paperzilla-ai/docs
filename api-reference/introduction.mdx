Paperzilla is primarily consumed through product surfaces:

- Web app project feed
- Email digests
- RSS/Atom feed URLs
- CLI (`pz`)
- MCP endpoint (`/api/mcp`)

This reference covers public paper records, RSS/Atom feeds and MCP.

Paper metadata can come from preprint servers or PubMed-indexed biomedical and clinical literature. For sources with revision tracking, `pdf_url` links to a PDF for that revision. If Paperzilla only knows a general PDF link, `pdf_url` is `null` and `publisher_pdf_url` contains the general link. The source landing page is in `url`. Its `url_kind` is `revision` for an exact version and `publisher` for a general page.

## Look up a paper revision

Use `GET /api/public/papers/{paper_ref}` with a Paperzilla paper UUID or eight-character short ID. When Paperzilla knows the source revision, the response includes `revision.source`, `revision.native_id` and `revision.version`. For example, two medRxiv records can share a DOI and have different paper IDs for v1 and v2.

Use `GET /api/public/papers/{paper_ref}/revisions` with either ID to see the versions Paperzilla has observed, highest numbered version first. Each entry has its own `paper_id`. To link to that version, open its `path` on `https://paperzilla.ai`. A publisher URL can open the latest version.

```bash
curl -sS https://paperzilla.ai/api/public/papers/49e21baa-2b67-4997-9285-b8b8017cb24d/revisions
```

The following excerpt shows the IDs and links.

```json
{
  "paper_id": "49e21baa-2b67-4997-9285-b8b8017cb24d",
  "revisions": [
    {
      "paper_id": "49e21baa-2b67-4997-9285-b8b8017cb24d",
      "version": "v2",
      "path": "/p/49e21baa-2b67-4997-9285-b8b8017cb24d"
    },
    {
      "paper_id": "af429483-f897-4696-a3e8-6c6ed6c0da5f",
      "version": "v1",
      "path": "/p/af429483-f897-4696-a3e8-6c6ed6c0da5f"
    }
  ]
}
```

### Revision dates in the output

Run `pz paper <paper-id> --revisions` to see the dates for each observed version. Add `--json` to include the precision and source of each date. The public REST endpoint and the MCP tool `paper_revisions` return the same fields in each `revisions` entry.

| CLI column | JSON field | Meaning |
| --- | --- | --- |
| `POSTED` | `posted` | When this version first became public at its source. Use it to decide when the version qualifies for a historical replay. |
| `PUBLISHED` | `published` | When a journal or proceedings published the version of record, if known. |
| `SEEN (UTC)` | `seen` | When Paperzilla ingested this version or its catalog record. Check `seen_basis` to distinguish the two. |

In this illustrative ChemRxiv entry, the source gives only the posting month. The journal publication date is unknown, so the CLI shows `—` and the three publication fields in JSON are `null`.

```json
{
  "version": "v2",
  "paper_id": "00000000-0000-4000-8000-000000000002",
  "path": "/p/00000000-0000-4000-8000-000000000002",
  "posted": "2024-02",
  "posted_precision": "month",
  "posted_basis": "crossref-posted",
  "published": null,
  "published_precision": null,
  "published_basis": null,
  "seen": "2026-11-20T09:14:00.000000Z",
  "seen_precision": "microsecond",
  "seen_basis": "paperzilla-ingested"
}
```

A `seen_basis` of `paperzilla-ingested` gives the earliest confirmed ingestion time for this revision. With `paperzilla-record-ingested`, `seen` gives the ingestion time for the returned `paper_id` while its revision label awaits verification.

Each `_basis` identifies the evidence for its date. For example, `crossref-posted` identifies the posting date in the Crossref deposit for that revision. For known `posted` and `published` dates, the precision is `day`, `month`, or `year`. The UTC ingestion timestamp has six fractional digits, so `seen_precision` is `microsecond` even when those digits are all zero.

`posted` and `published` preserve the source’s precision as `YYYY-MM-DD`, `YYYY-MM`, or `YYYY`. For a replay, treat a month as its last day and a year as December 31. For example, `2024-02` first qualifies on February 29. If `posted` is missing, leave that version out of a date-gated replay. Use the selected version’s `paper_id` to request its Markdown.

arXiv supplies version submission dates. bioRxiv and medRxiv supply posting dates. IACR ePrint supplies a dated revision history or an initial approval date. For a numbered ChemRxiv DOI, Paperzilla uses the Crossref posting date when the deposit identifies that version. For PubMed, a later version needs its own version date. A first journal version can also use an online or issue date. A preprint’s subsequent journal publication requires separate evidence. Older records can have gaps wherever the stored source data cannot establish the date or its precision.

History can start at v3 or contain v3 and v1 with a gap. Paperzilla tracks revisions for arXiv, bioRxiv, medRxiv, ChemRxiv, PubMed and IACR ePrint. Other sources return an empty `revisions` list. An entry labeled `unversioned` is a recorded ChemRxiv or IACR version whose number is unknown.
