Comenta artículos con Claude en Slack y usa Cowork para preparar un informe entre semana que puedas compartir en Slack.

Claude en Slack se encarga de la conversación. Cowork lee tu proyecto mediante Paperzilla MCP y prepara el informe programado.

## Antes de empezar

<Info>**Conecta Paperzilla en Claude primero.** Sigue los pasos para [instalar el plugin de Paperzilla en Claude](/es/guides/claude#open-the-connection-setup) y conecta tu cuenta. Después vuelve a esta guía para configurar Slack y Cowork.</Info>

- Conecta Claude a tu espacio de Slack e inicia un mensaje directo con Claude. Pídele que enumere tus proyectos para comprobar que la conversación de Slack puede usar tu conexión con Paperzilla. Consulta [Claude en Slack](https://claude.com/docs/claude-tag/overview).
- Abre Cowork y comprueba que puede enumerar los mismos proyectos. Para enviar desde Cowork después de revisar un borrador, conecta el [conector de Slack](https://claude.com/connectors/slack) en Claude y comprueba que puede acceder al destino. También puedes pegar el borrador en Slack.
- Elige un proyecto de Paperzilla para este flujo.
- Prepara una frase breve sobre «nuestro trabajo» si Claude aún no lo conoce. Ejemplo: `Our work is evaluation infrastructure for coding agents.`

## Cómo funciona este conjunto

- Debate artículos con Claude en Slack.
- Claude lee los datos de Paperzilla cuando el conector está disponible en la conversación de Slack o en la tarea de Cowork.
- Para el informe entre semana, Cowork ejecuta una tarea programada y prepara una publicación para Slack.
- Revisa el borrador en Cowork antes de compartirlo con tu equipo.

## Caso de uso 1: debate de artículos bajo demanda

Empieza con un mensaje directo a Claude en Slack. En un canal compartido, otras personas pueden ver las respuestas de `@Claude`. Comparte solo los datos de los artículos que quieras mostrar en ese canal.

Primero pide los artículos más recientes de un proyecto:

```text
Use my Paperzilla project `Agents evaluation`.
Our work: we build evaluation infrastructure for coding agents.

Pull the latest papers from this project and show the top 5.
For each one, include the title, date, source, and whether it looks Must Read or Related.
```

Después pide los metadatos de un artículo:

```text
Open the second paper and show the metadata only.
Include authors, publication date, source, URL, and the Paperzilla ID you used.
```

Después obtén el Markdown y relaciónalo con el contexto del equipo:

```text
Fetch the markdown for that paper.
Summarize the contribution, method, results, and limits.
Then explain why it matters for our work.
```

Continúa el debate:

```text
Given our current work, should we read this now, keep it as Related, or ignore it this week?
Defend the recommendation.
```

Las buenas respuestas para este flujo deben:

- mantener visibles el nombre del proyecto y el contexto de «nuestro trabajo»
- separar los metadatos de la interpretación
- explicar la relevancia según tu trabajo real, no según una importancia genérica
- facilitar que el debate continúe en la misma conversación de Slack

Para compartir los resultados en un canal, revisa el borrador en el mensaje directo y publica lo que quieras mostrar al equipo.

## Caso de uso 2: informe entre semana en Slack

Este patrón se ejecuta en Cowork los días laborables y prepara un informe para Slack.

Abre **Scheduled** en Claude, selecciona **New task** y añade las instrucciones de abajo. Elige los días laborables y la hora que prefieras. Ejecuta la tarea guardada una vez para comprobar que puede leer Paperzilla.

```text
Use my Paperzilla project `Agents evaluation`.
Our work: we build evaluation infrastructure for coding agents.

Every weekday morning:
1. Check papers added to the feed in the last 72 hours on Mondays and 24 hours on other weekdays.
2. Keep the brief concise.
3. For each selected paper, include the title, one short summary, and one sentence on why it is relevant to our work.
4. Include the project name, today's date, the time window, and the number of papers checked.
5. If there are no new papers, say that explicitly.
6. Draft a Slack post for #research-briefs and show it to me first.
```

Revisa cada resultado en **Scheduled**. Cópialo en Slack o pide a Claude que envíe el borrador revisado mediante el conector de Slack. Si Claude te pide autorización, confirma el mensaje y el destino antes de enviarlo.

El formato esperado del informe es:

- nombre del proyecto y fecha
- número de artículos nuevos revisados
- para cada artículo seleccionado, un resumen breve y una frase sobre su relevancia para el trabajo
- una línea clara de «hoy no hay artículos nuevos» cuando ninguno cumpla los criterios

<Note>Cowork puede ejecutar en remoto las tareas programadas que usan conectores. Si la tarea necesita archivos o aplicaciones locales, mantén el equipo activo y Claude Desktop abierto.</Note>

Consulta cómo [programar tareas recurrentes en Claude Cowork](https://support.claude.com/en/articles/13854387-schedule-recurring-tasks-in-claude-cowork) y [usar conectores interactivos en Claude](https://support.claude.com/en/articles/13454812-use-interactive-connectors-in-claude) para ver las opciones de programación y los controles de Slack.

## Límites y solución de problemas

- Si Claude no puede acceder a Paperzilla en Slack, prueba en un mensaje directo. Si usas un canal, [comprueba a qué conectores tiene acceso Claude Tag](https://claude.com/docs/claude-tag/overview) y vuelve a intentarlo.
- Si Cowork no puede enviar el borrador revisado a Slack, comprueba los permisos del conector de Slack para ese canal o pega el borrador.
- Si la tarea programada no se ejecuta, comprueba el horario, las aprobaciones de los conectores y si requiere tu equipo.
- Si el agente no devuelve artículos, confirma que el proyecto está activo y ya tiene elementos en la lista.
- Si `paper_markdown_get` devuelve `queued`, vuelve a intentarlo más tarde. Si devuelve `unavailable`, usa el resumen del artículo y la información disponible e indícalo en el informe.
