Conecta un cliente de IA a tu cuenta de Paperzilla en `https://paperzilla.ai/api/mcp` mediante Streamable HTTP y OAuth.

Necesitas una cuenta. Las cuentas Free y de vista previa pueden leer digests públicos y artículos del catálogo sin crear un proyecto. Los feeds personales requieren un proyecto propio. No tener proyectos no impide la conexión.

## Conectar

1. Añade la URL del servidor en la configuración MCP del cliente y selecciona OAuth.
2. Inicia sesión o crea una cuenta de Paperzilla en la ventana del navegador.
3. Revisa la identidad del cliente, la cuenta y los permisos. Selecciona **Permitir** o **Denegar**.
4. Vuelve al cliente y pide: «Busca digests públicos sobre aprendizaje automático».

Para conectar no hace falta crear un proyecto, iniciar una prueba ni introducir datos de pago. Al iniciar sesión se retoma la solicitud de consentimiento. Si caduca, inicia la conexión de nuevo desde el cliente en el mismo navegador.

En [Conectar clientes de IA](https://paperzilla.ai/ai-connections) puedes copiar la URL, consultar los permisos y el último uso, o revocar una conexión. La revocación es inmediata. Para volver a conceder acceso, reconecta desde el cliente.

## Configuración por cliente

### ChatGPT

Para una prueba privada, abre **Plugins → Add → Add custom MCP server** en ChatGPT. Introduce la URL del servidor y selecciona **OAuth**. Las opciones disponibles dependen de tu cuenta y espacio de trabajo. Consulta la [configuración MCP de ChatGPT](https://developers.openai.com/api/docs/guides/custom-mcp-server).

Después del descubrimiento, abre **Advanced OAuth settings**. Conserva la identidad descubierta **Client Identifier Metadata Document (CIMD)**; no necesitas un secreto de cliente manual. Mantén los permisos funcionales que quieras e introduce `offline_access` en **Base scopes** para permitir la renovación. Después, selecciona **Create as a plugin** e **Install**. Conecta tu cuenta de Paperzilla mediante el consentimiento en el navegador, vuelve a ChatGPT y selecciona el plugin en la conversación.

Si Paperzilla está disponible en el directorio, instala esa integración y conecta tu cuenta. La publicación en el directorio es un paso separado; una conexión personalizada no implica una integración aprobada.

### Claude

Añade un conector personalizado con la URL del servidor en la configuración de conectores de Claude. Conecta y autoriza el acceso a Paperzilla. En **Tool permissions** del conector, configura las herramientas de solo lectura como **Always allow** para evitar confirmaciones repetidas y mantén `paper_markdown_request` en **Needs approval**. Consulta la [guía de Claude](/es/guides/claude).

### OpenClaw

Abre **Settings → MCP → Add server**. Asigna el nombre `paperzilla`, elige **Streamable HTTP** e introduce `https://paperzilla.ai/api/mcp`. Después de añadirlo, configura OAuth en el editor de MCP y pulsa **Sign in** para autorizar el acceso en Paperzilla.

Consulta [Usar Paperzilla MCP con OpenClaw](/es/guides/openclaw-mcp) para ver la configuración completa, los permisos, ejemplos de solicitudes y la solución de problemas. Puedes empezar con una cuenta Free y sin proyectos.

### MCP Inspector

Abre el [MCP Inspector oficial](https://modelcontextprotocol.io/docs/tools/inspector), selecciona Streamable HTTP, introduce la URL y completa OAuth. Solicita los cuatro permisos siguientes, conecta, lista las herramientas y llama a `account_status`. Prueba los digests públicos antes de los proyectos privados.

### Codex y agentes personalizados

Consulta [Codex](/es/guides/codex). Los agentes personalizados deben utilizar OAuth y almacenamiento seguro de credenciales del SDK MCP. El flujo usa código de autorización, PKCE S256 y el recurso anunciado. Los clientes públicos se registran con `token_endpoint_auth_method: "none"`. No hay flujo client-credentials. Consulta la [referencia](/es/api-reference/mcp).

## Permisos

| Scope | Permite |
|---|---|
| `catalog:read` | Digests públicos, metadatos del catálogo y Markdown preparado |
| `projects:read` | Todos los proyectos propios actuales y futuros y sus feeds |
| `markdown:generate` | Solicitar Markdown de un artículo existente |
| `offline_access` | Mantener la conexión con credenciales de renovación rotatorias |

Los clientes pueden solicitar un subconjunto. Un permiso ausente devuelve una acción de autorización para esa herramienta. Las credenciales de inicio de sesión de Paperzilla no se entregan al cliente de IA.

## Leer y preparar Markdown

`paper_get` acepta ID/URL de Paperzilla, DOI o URL de una fuente compatible. Solo consulta el catálogo existente: no importa artículos desconocidos y devuelve candidatos si la referencia es ambigua.

`paper_markdown_get` lee contenido preparado o consulta su estado. Para solicitar el procesamiento explícitamente, usa `paper_markdown_request`. Es una acción de escritura con un límite de 10 solicitudes por minuto y cuenta, compartido entre clientes y sin cuota diaria. En conjunto, las herramientas permiten 120 llamadas por minuto y cuenta. Repetir una solicitud no duplica el trabajo.

Los estados normales incluyen `ready`, `not_ready`, `queued`, `unavailable`, `cooldown` y `rate_limited`. Espera antes de consultar trabajos pendientes y respeta `retry_after_seconds` cuando aparezca. Una fuente no disponible no es un error de autenticación.

Las listas usan `limit`, `offset` y `next_offset`. Continúa la búsqueda pública mientras haya `next_offset`, incluso si una página filtrada está vacía. Cada página Markdown tiene como máximo 20.000 caracteres; pasa `revision` y `next_offset` para continuar. Con `restart_required`, vuelve a empezar desde cero.

## Proyectos y digests públicos

Una serie de digests se identifica por `project_id`; cada entrega publicada tiene su propio `issue_id`. Usa `public_digests_search`, después `public_digest_issues_list` y finalmente `public_digest_get`.

`projects_list`, `projects_get`, `feed_get` y `feed_search` leen tus proyectos. `needs_project` incluye un enlace para crear uno y no bloquea las herramientas públicas. Los digests públicos respetan las mismas restricciones de visibilidad y vista previa que el sitio web.

## Reconectar tras la sustitución

Las claves API antiguas, las URL con credenciales y los nombres antiguos de herramientas se retiran. Elimina la conexión anterior y añade la URL canónica con OAuth. El cliente gestiona las credenciales en la cabecera Authorization.

Los tokens de acceso duran 15 minutos. Con `offline_access`, el cliente rota los tokens de renovación, que caducan tras 30 días de inactividad. Revocar la conexión o desactivar o eliminar la cuenta invalida su acceso. Si falla la renovación, reconecta en lugar de reutilizar un token antiguo.

La [referencia](/es/api-reference/mcp) enumera todas las herramientas. Esta versión no crea ni edita proyectos, no escribe valoraciones, no importa artículos ni incorpora interfaz dentro del cliente.
