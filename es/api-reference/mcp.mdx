El recurso canónico Streamable HTTP es `https://paperzilla.ai/api/mcp`. Usa Python MCP SDK 2.3.0 con el protocolo por solicitud `2026-07-28` y compatibilidad estándar con clientes `2025-11-25`. Deja la negociación y los formatos de solicitud al SDK.

## OAuth

- Emisor: `https://paperzilla.ai/api/oauth`
- Metadatos de autorización: `https://paperzilla.ai/.well-known/oauth-authorization-server/api/oauth`
- Metadatos del recurso: `https://paperzilla.ai/.well-known/oauth-protected-resource/api/mcp`
- Endpoints bajo el emisor: `/authorize`, `/token`, `/register`, `/revoke`.

Usa código de autorización con PKCE S256 obligatorio. Incluye `resource=https://paperzilla.ai/api/mcp` al autorizar e intercambiar el código. La URL de retorno debe coincidir con la registrada; las direcciones loopback nativas siguen las reglas del SDK. Se admiten CIMD, registro dinámico y clientes públicos prerregistrados con `token_endpoint_auth_method` igual a `none`. No hay flujo máquina a máquina.

Los permisos funcionales son `catalog:read`, `projects:read` y `markdown:generate`. Solicita `offline_access` para renovar el acceso. Los clientes pueden pedir un subconjunto. Los códigos duran cinco minutos y son de un solo uso. Los tokens de acceso duran 15 minutos. Los de renovación rotan y caducan tras 30 días de inactividad; reutilizarlos revoca la conexión. Guarda cada reemplazo y serializa las renovaciones.

Envía únicamente el token OAuth dedicado en Authorization, nunca la sesión Supabase. Las claves antiguas y las credenciales en la URL se rechazan. Los desafíos de autenticación indican los metadatos de descubrimiento; los permisos insuficientes devuelven metadatos `mcp/www_authenticate`.

## Herramientas

| Herramienta | Parámetros | Permiso |
|---|---|---|
| `account_status` | ninguno | `catalog:read` |
| `projects_list` | `limit`, `offset` | `projects:read` |
| `projects_get` | `project_id` UUID | `projects:read` |
| `feed_get` | `project_id`, opcionales `must_read`, `since` ISO, `limit`, `offset` | `projects:read` |
| `feed_search` | `project_id`, `query` (3–200 caracteres), opcionales `must_read`, `limit`, `offset` | `projects:read` |
| `public_digests_search` | opcionales `query` (hasta 200 caracteres), `limit`, `offset` | `catalog:read` |
| `public_digest_issues_list` | `project_id` de la serie, `limit`, `offset` | `catalog:read` |
| `public_digest_get` | `issue` UUID/ID corto/URL de Paperzilla, `limit`, `offset` | `catalog:read` |
| `paper_get` | `reference` ID/URL/DOI | `catalog:read` |
| `paper_markdown_get` | `reference`, opcionales `offset` de caracteres, `revision` | `catalog:read` |
| `paper_markdown_request` | `reference` | `markdown:generate` |

`reference` admite un UUID, un ID corto de ocho caracteres o una URL de artículo de Paperzilla; un DOI (incluidos enlaces de doi.org); `PMID 12345678` o `pmid:12345678`; un identificador IACR ePrint `YYYY/NNN`; y URL de artículos de arXiv, PubMed, IACR ePrint, bioRxiv y medRxiv. Se admiten enlaces PDF de arXiv e IACR. Las URL con versión de arXiv, bioRxiv y medRxiv se resuelven en el catálogo existente. Las URL de bioRxiv y medRxiv usan `/content/10.1101/...`. Otras URL devuelven `not_found` con indicaciones sobre los formatos admitidos. Paperzilla nunca descarga la URL proporcionada ni importa un artículo ausente.

Las listas devuelven 20 resultados por defecto, con un rango de 1–50. Continúa con `next_offset` hasta que sea null. Markdown usa páginas de 20.000 caracteres y un hash de revisión. Solo `paper_markdown_request` escribe. Su límite de 10 solicitudes por minuto se comparte entre todos los clientes de la cuenta. El límite general es de 120 llamadas por minuto y cuenta.

Las respuestas incluyen datos estructurados y texto legible. `needs_project`, `not_found`, `ambiguous`, `not_ready`, `queued`, `cooldown`, `unavailable`, `restart_required` y `rate_limited` son estados normales. No se exponen identificadores internos de trabajos ni contenido oculto de vistas previas. No hay alias ni prompts antiguos. Atom sigue disponible fuera de MCP.

## Gestión de conexiones

`GET /api/oauth/connections` y `DELETE /api/oauth/connections/{grant_id}` requieren la sesión ordinaria de Paperzilla, nunca tokens MCP. El consentimiento está ligado a una solicitud pendiente y a una cookie del mismo navegador. Los clientes deben seguir `/authorize`.

Consulta la [configuración](/es/guides/mcp), la [especificación de autorización MCP](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization) y el [SDK Python](https://py.sdk.modelcontextprotocol.io/whats-new/).
