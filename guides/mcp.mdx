Connect an AI client to your Paperzilla account at `https://paperzilla.ai/api/mcp` using Streamable HTTP and OAuth.

An account is required. Free and preview accounts can read public digests and catalog papers without creating a project. Personal feeds require an owned project. A missing project does not prevent connection.

## Connect

1. Add the server URL in your client's MCP settings and select OAuth.
2. Sign in or create a Paperzilla account in the browser window.
3. Check the client identity, account, and permissions. Select **Allow** or **Deny**.
4. Return to the client and ask: “Find public digests about machine learning.”

You do not need to create a project, start a trial, or enter payment details to connect. Sign-in resumes the pending consent request. If it expires, start the connection again from your client in the same browser.

Open [Connect AI clients](https://paperzilla.ai/ai-connections) to copy the URL, inspect permissions and last use, or revoke a connection. Revocation takes effect immediately. Reconnect from your client when you want to grant access again.

## Client setup

### ChatGPT

To add Paperzilla to ChatGPT, open **Plugins → Add → Add custom MCP server**. Enter the server URL and select **OAuth**. Available controls depend on your account and workspace settings. See [ChatGPT's custom MCP setup](https://developers.openai.com/api/docs/guides/custom-mcp-server).

After discovery, open **Advanced OAuth settings**. Keep the discovered **Client Identifier Metadata Document (CIMD)** identity; you do not need a manual client secret. Retain the functional permissions you want and enter `offline_access` in **Base scopes** to allow refresh. Then select **Create as a plugin** and **Install**. Connect your Paperzilla account through the browser consent flow, return to ChatGPT, and select the plugin in your conversation.

If Paperzilla becomes available in the directory, install that listing and connect your account. Directory publication is a separate step; a custom connection does not imply an approved listing.

### Claude

If you have the Paperzilla plugin, open **Settings → Customize → Plugins → Paperzilla → Connectors → Connect**. Installing the plugin does not connect its account. Claude may show **Connect** twice: first to add the connector, then, if it shows **Not connected**, to sign in to Paperzilla; **Connected** marks completion. If you do not have the plugin, add a custom connector with the server URL. On the authentication screen, choose **Sign in now** and **Use Claude’s published identity**, leave request headers empty, and select **Add**. Sign in to Paperzilla, approve access, then return to the original chat and ask Claude to continue.

In the connector's **Tool permissions**, set **all Paperzilla read-only tools** to **Always allow** for smooth lookups and morning briefs: otherwise, calls can pause for approval depending on the task's approval mode, and an unattended brief may not finish. Keep `paper_markdown_request`, `feedback_set`, and `feedback_clear` on **Needs approval**. These tools start processing or change saved feedback. See [the complete Claude setup, screen choices, and troubleshooting](/guides/claude).

### OpenClaw

Install the [Paperzilla MCP plugin](https://clawhub.ai/pors/plugins/paperzilla-mcp) for its OAuth connection and Morning Brief skill. Use OpenClaw 2026.10.8 or later. In **Plugins**, find **Paperzilla MCP** by `pors`, then install and enable it. You can also install it from the command line:

```sh
openclaw plugins install clawhub:@pors/paperzilla-mcp
```

Then open **Paperzilla MCP → Overview → Accounts**, select **Connect** next to `paperzilla`, and approve access in Paperzilla. Installing the plugin does not connect your account. The plugin supplies the server, so do not add it again in **Settings → MCP**.

To connect without the plugin, open **Settings → MCP → Add server**. Name the server `paperzilla`, choose **Streamable HTTP**, and enter `https://paperzilla.ai/api/mcp`. After adding it, configure OAuth in the scoped MCP editor, then select **Sign in** and approve access in Paperzilla.

Follow [Use Paperzilla MCP with OpenClaw](/guides/openclaw-mcp) for the complete setup, configuration example, permissions, example requests, and troubleshooting. You can begin with a Free account and no projects.

### MCP Inspector

Start the official [MCP Inspector](https://modelcontextprotocol.io/docs/tools/inspector), select Streamable HTTP, enter the URL, and run its OAuth flow. Request the scopes below, connect, list tools, and call `account_status`. Then search public digests before testing private project tools.

### Codex and custom agents

See [Codex](/guides/codex). Custom agents should use their MCP SDK's OAuth client and secure credential storage. Use authorization-code flow with PKCE S256 and the advertised resource; public clients register with `token_endpoint_auth_method: "none"`. There is no client-credentials grant. See the [protocol reference](/api-reference/mcp).

## Permissions

| Scope | Allows |
|---|---|
| `catalog:read` | Public digests, canonical paper metadata, prepared Markdown |
| `projects:read` | All current and future projects owned by your account and their feeds |
| `feedback:write` | Rate, star, or clear feedback on papers in your own project feeds |
| `markdown:generate` | Request Markdown processing for an existing paper |
| `offline_access` | Stay connected using rotating refresh credentials |

Clients can request a subset. A missing permission produces an authorization action for that tool. Paperzilla sign-in credentials remain separate from the credentials given to your AI client.

## Read and prepare Markdown

Use `paper_get` with a Paperzilla ID/URL, DOI, or supported source URL. Paperzilla searches its existing catalog. A missing paper is not imported, and ambiguous references return candidates.

`paper_markdown_get` only reads existing content or reports availability. If you explicitly want processing, use `paper_markdown_request`. Generation is a write action, limited to 10 requests per minute per account across clients, with no daily quota. All tools together allow 120 calls per minute per account. Repeating a request does not queue duplicate work.

Normal states include `ready`, `not_ready`, `queued`, `unavailable`, `cooldown`, and `rate_limited`. Wait before retrying queued work; respect `retry_after_seconds` when returned. An unavailable source or cooldown is not an authentication failure.

Listings use `limit`, `offset`, and `next_offset`. Continue public searches while `next_offset` is present, even if a filtered page is empty. Markdown pages contain at most 20,000 characters; pass the returned `revision` and `next_offset` to continue. `restart_required` means read again from offset zero.

## Projects and public digests

A digest series is identified by `project_id`; each published issue has its own `issue_id`. Use `public_digests_search`, then `public_digest_issues_list`, then `public_digest_get`.

`projects_list`, `projects_get`, `feed_get`, and `feed_search` read your owned projects. `needs_project` includes a setup link. Public tools continue to work. Public digest reads follow the same visibility and preview limits as the website and do not expose hidden preview content.

## Give feedback on your own feed

Ask your client to “Star the second paper in this project,” “Mark this paper as not relevant to this project,” or “Clear my feedback on that paper.” The client uses `feedback_set` or `feedback_clear` with `feedback:write` permission. Feedback applies to one item in your own project feed, not to the canonical paper or another user's public digest.

The client must identify the exact feed item before saving feedback. If a paper appears in several projects or the target is unclear, specify the project and paper. Ranking papers in a brief does not itself submit feedback. A successful call confirms the saved vote or that feedback was cleared.

Existing connections do not automatically gain write access. Refresh the client's tool list if needed, request `feedback:write`, and reconnect to review and approve the new permission. Reading a feed still uses `projects:read`; feedback permission does not grant private-project reads.

## Reconnecting after the replacement

Old API keys, credential-bearing URLs, and old tool names are retired. Remove the old connection and add the canonical URL with OAuth. Credentials are accepted only in Authorization headers managed by your client.

Access tokens last 15 minutes. With your consent to `offline_access`, clients rotate refresh tokens automatically; refresh access expires after 30 days of inactivity. Revoking a connection, disabling the account, or deleting it invalidates its access. If refresh fails, reconnect rather than retrying an old refresh token.

The [tool reference](/api-reference/mcp) lists the complete surface. Project creation/editing, paper imports, and embedded client UI are outside this release.
