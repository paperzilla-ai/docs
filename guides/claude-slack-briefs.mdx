Discuss papers with Claude in Slack and use Cowork to prepare a weekday brief you can share in Slack.

Claude in Slack handles the discussion. Cowork reads your project through Paperzilla MCP and prepares the scheduled brief.

## Before you start

<Info>**Connect Paperzilla in Claude first.** Follow the [Paperzilla plugin setup in Claude](/guides/claude#open-the-connection-setup) and connect your account. Then return here to set up Slack and Cowork.</Info>

- Connect Claude to your Slack workspace and start a DM with Claude. Ask it to list your Paperzilla projects to confirm the Slack conversation can use your connection. See [Claude in Slack](https://claude.com/docs/claude-tag/overview).
- Open Cowork and check that it can list the same projects. To send from Cowork after reviewing a draft, connect the [Slack connector](https://claude.com/connectors/slack) in Claude and check that it can access your destination. You can also paste the draft into Slack yourself.
- Pick one Paperzilla project for this workflow.
- Prepare one short sentence for "our work" if Claude does not already know it. Example: `Our work is evaluation infrastructure for coding agents.`

## How this stack works

- You discuss papers with Claude in Slack.
- Claude reads your Paperzilla data when the Paperzilla connector is available in the Slack conversation or Cowork task.
- For the weekday brief, Cowork runs a scheduled task and prepares a Slack-ready post.
- Review the draft in Cowork before sharing it with your team.

## Use case 1: on-demand paper discussion

Start in a DM with Claude in Slack. In a shared channel, `@Claude` replies can be visible to other people. Share only paper details you intend the channel to see.

First ask for the latest papers from one project:

```text
Use my Paperzilla project `Agents evaluation`.
Our work: we build evaluation infrastructure for coding agents.

Pull the latest papers from this project and show the top 5.
For each one, include the title, date, source, and whether it looks Must Read or Related.
```

Then ask for metadata for one paper:

```text
Open the second paper and show the metadata only.
Include authors, publication date, source, URL, and the Paperzilla ID you used.
```

Then fetch markdown and connect it back to your team context:

```text
Fetch the markdown for that paper.
Summarize the contribution, method, results, and limits.
Then explain why it matters for our work.
```

Then keep the discussion going:

```text
Given our current work, should we read this now, keep it as Related, or ignore it this week?
Defend the recommendation.
```

Good replies for this flow should:

- keep the project name and "our work" context in view
- separate metadata from interpretation
- explain relevance in terms of your actual work, not generic importance
- make it easy to continue the discussion in the same Slack conversation

To share results in a channel, review your draft in the DM first and post the parts you want the team to see.

## Use case 2: weekday research brief in Slack

This pattern runs in Cowork on weekdays and prepares a brief for Slack.

Open **Scheduled** in Claude, select **New task**, and add the prompt below. Choose weekdays and your preferred time. Run the saved task once to check that it can read Paperzilla.

```text
Use my Paperzilla project `Agents evaluation`.
Our work: we build evaluation infrastructure for coding agents.

Every weekday morning:
1. Check papers added to the feed in the last 72 hours on Mondays and 24 hours on other weekdays.
2. Keep the brief concise.
3. For each selected paper, include the title, one short summary, and one sentence on why it is relevant to our work.
4. Include the project name, today's date, the time window, and the number of papers checked.
5. If there are no new papers, say that explicitly.
6. Draft a Slack post for #research-briefs and show it to me first.
```

Review each result in **Scheduled**. Copy it to Slack or ask Claude to send the reviewed draft with the Slack connector. If Claude requests approval, confirm the message and destination before sending.

The expected brief format is:

- project name and date
- how many new papers were checked
- for each selected paper, one short summary and one sentence on why it is relevant to your work
- a clear "no new papers today" line when nothing new qualifies

<Note>Cowork can run connector-based scheduled tasks remotely. If your task requires local files or apps, keep the computer awake and Claude Desktop open.</Note>

See [Schedule recurring tasks in Claude Cowork](https://support.claude.com/en/articles/13854387-schedule-recurring-tasks-in-claude-cowork) and [Use interactive connectors in Claude](https://support.claude.com/en/articles/13454812-use-interactive-connectors-in-claude) for the scheduling and Slack controls.

## Limits and troubleshooting

- If Claude cannot access Paperzilla in Slack, test in a DM. For a channel, [check the connectors Claude Tag can access](https://claude.com/docs/claude-tag/overview) and try again.
- If Cowork cannot send the reviewed draft to Slack, check the Slack connector’s permissions for that channel or paste the draft yourself.
- If the scheduled task does not run, check its schedule, connector approvals, and whether it requires your computer.
- If the agent returns no papers, confirm the project is active and already has feed items.
- If `paper_markdown_get` returns `queued`, try again later. If it returns `unavailable`, use the abstract and other available information and say so in the brief.
